# Portfolio

Static portfolio; open [index.html](index.html) locally or deploy the repository through GitHub Pages. Existing testimonials remain unchanged. Contact uses a direct email link; no PHP/email API is required.

## GitHub Pages

In this repository's Settings > Pages, select GitHub Actions as the build source. The [Pages workflow](.github/workflows/pages.yml) runs on pushes to `main` and can also be started manually from Actions. It installs with pnpm 10.4.1 and the frozen lockfile, runs all tests and the static checker, then checks the staged site again before publishing through the `github-pages` environment.

The upload path is `${{ runner.temp }}/portfolio-pages`, containing only `index.html` and `assets/`. Asset copying excludes hidden files, private/test/backup directories, and backup suffixes. The old `forms/` PHP handler is unused and is not published. Repository metadata, scripts, tests, dependencies, and private submissions are not uploaded. No deployment secrets or paid account are needed for Pages on a public repository.

## Local Checks

From the portfolio directory, with Node.js 20 or newer and pnpm 10.4.1 installed (matching the package manifest):

```powershell
pnpm install --frozen-lockfile --ignore-scripts
pnpm test
pnpm run check:static
```

The development dependencies are HTML/CSS parsers used only by local checks; the deployed page does not use a package manager or require a build. If pnpm is unavailable or a local shim selects a different version, run `npm.cmd exec --yes --package=pnpm@10.4.1 -- pnpm` followed by the same arguments. On non-Windows systems, use `npm` instead of `npm.cmd` for this fallback.

To run just the testimonial regressions without installing dependencies:

```powershell
node --test tests/testimonials.test.cjs
```

The tests execute the renderer with a minimal DOM and the real publisher CLI copied into temporary directories, using only fictional input. They verify script-sensitive escaping, literal-text rendering, exclusion of private/unselected data, consent rejection without changing an existing output, and replacement/removal of omitted IDs. They also require the actual public approved list to remain empty. The navigation test executes the main script with minimal DOM and vendor stubs. No test publishes a real testimonial, submits Google Forms, or reads private submissions. Temporary fixtures are removed after each test.

The offline static checker starts at `index.html`, follows reachable local HTML pages and their `href`, `src`, and `poster` references, and checks local stylesheet `url(...)` and `@import` references recursively. It checks exact filename case, file existence, HTML ID fragments, Google Forms public view-link structure and consistent destinations, and basic single-address `mailto` syntax/consistency. Basic markup checks cover document language/title/H1, duplicate IDs, image alt attributes (including valid empty decorative alt), action names, non-native action focus attributes, and `noopener` for new-tab links. Broken temporary fixtures verify that these checks actually fail.

Limitations: this is not an accessibility audit or external-link availability check. It does not contact Google, resolve shortened Forms URLs, verify the form's ownership/settings/consent fields, test email delivery, validate image/font contents, or inspect URLs generated by JavaScript, inline styles, or `srcset`. Action names are a markup heuristic, not a browser-computed accessible name. Minimal DOM tests do not verify layout, browser keyboard behavior, screen readers, contrast, focus order, or vendor carousel/lightbox behavior. Original HTML testimonials are preserved and not re-approved by these checks.

## Google Forms Testimonials

The About/testimonial section and Contact section link to the public [testimonial form](https://docs.google.com/forms/d/e/1FAIpQLSde5uBjB-ZtUXQoh7Z_FmMYlTrGpFGiE9XkUkEGI-B2Q50Wog/viewform?usp=dialog). No Forms API key, OAuth integration, Apps Script, or public response spreadsheet is used.

In Google Forms, enable Responses -> More -> Get email notifications for new responses. Keep View results summary off and any response spreadsheet private. Review the exact quote, display name, role, and publication permission. A notification or form submission is not approval. Requests for private feedback must never be published.

## Approve And Publish

After reviewing responses, create a local `private/submissions.json` array containing the submissions you want to consider. This directory is ignored by Git. Assign a unique local ID to each response. Map Display Name to `name`, Role / Relationship to `role`, and Testimonial to `quote`. Set `publicationConsent` to boolean `true` only when the respondent explicitly selected Yes. Never infer consent from a nonempty response. No raw response export is fetched by the site.

Example schema (fictional; do not publish this example):

```json
[
	{
		"id": "response-001",
		"name": "Alex Example",
		"role": "Project collaborator",
		"quote": "A thoughtful collaborator.",
		"publicationConsent": true
	}
]
```

From the portfolio directory, explicitly select the complete set of new testimonials to publish:

```powershell
node scripts/approve-testimonials.cjs private/submissions.json response-001 response-002
pnpm test
pnpm run check:static
git diff -- assets/js/approved-testimonials.js
```

The command replaces the generated new-testimonial list with the selected IDs; include previously approved IDs you want to retain. It rejects missing consent, duplicate IDs, invalid fields, and oversized quotes. Only ID, name, role, and quote are exported; emails/timestamps/other private fields are excluded. The browser renders quotes as text, not HTML. Original HTML testimonials are separate and preserved.

The current maintenance baseline intentionally has no newly approved testimonials. Publishing real entries is a separate, explicitly authorized task; the empty-list regression must be deliberately reconsidered for that task. Passing no IDs is rejected rather than clearing the list. To remove every generated entry, reset `assets/js/approved-testimonials.js` to `window.APPROVED_TESTIMONIALS = [];` and review the diff. An omitted ID disappears on a fresh page load; the renderer runs once before the carousel initializes and does not reconcile an already-open page.

Preview the site, review the public diff, then commit/push through your usual deployment process. Only after the site is deployed do approved entries appear publicly. Google Forms does not automatically publish them. For removal, regenerate without that ID (or reset the generated array to empty) and redeploy; original testimonials require editing the HTML. Do not change a person's wording materially without their agreement. Photo uploads are not supported by this flow.
